# Инструменты MCP

В обычной работе LINZA показывает 7 основных MCP-инструментов. Самый важный вход для агента: `agent_workspace`. Через него проходят карта папки, входящие материалы, ревью, применение выбранных карточек, память, trace-записи и экспорт контекста.

Начните с `guide_next_steps` или `agent_workspace(action="doctor")`, если нужно понять состояние папки. Дальше обычно хватает поиска, чтения точного файла и карточек ревью.

На практике с LINZA можно говорить обычным языком: «проверь папку», «покажи карту», «найди связанные материалы», «подготовь пакет контекста». Названия ниже нужны как справочник того, что MCP-клиент вызывает во время работы.

## Основные инструменты

| Инструмент | Назначение |
| --- | --- |
| `guide_next_steps` | Показать следующий безопасный шаг |
| `agent_workspace` | Единый вход для карты, входящих материалов, ревью, применения, обучения, связей, памяти, trace-записей и экспорта контекста |
| `index_all` | Обновить индекс Markdown-папки |
| `search` | Найти заметки через семантический и лексический поиск |
| `read_file` | Прочитать точный Markdown-файл |
| `get_stats` | Показать счетчики сайдкара |
| `scan_vault` | Проверить папку без записи |

## Действия в `agent_workspace`

`agent_workspace` держит основной рабочий сценарий внутри одного инструмента. Агент может показать карту, разобрать входящие материалы, вынести карточки на ревью, применить выбранные ID, найти принятую память и собрать пакет контекста.

| Действие | Назначение |
| --- | --- |
| `doctor` | Проверить готовность сайдкара, индекса, входящих материалов, ревью и calibr |
| `map` | Показать карту рабочей папки без записи |
| `ingest_artifacts` | Импортировать входящие материалы в сайдкар |
| `analyze_inbox` | Разобрать входящие артефакты |
| `review_next` | Показать следующие `aw-*` карточки |
| `apply_review_items` | Предпросмотр или применение выбранных `aw-*` ID |
| `history` | Показать историю принятых и отозванных решений |
| `revoke_approval` | Мягко отозвать принятое решение через `approval_id` |
| `teach` | Выбрать учебные карточки |
| `grow` | Подобрать новые карточки по принятым примерам |
| `connect` | Объяснить связь двух узлов |
| `search_memory` | Найти артефакты и принятую память |
| `export_context` | Собрать Markdown-пакет контекста |
| `record_trace` | Записать trace работы агента |
| `analyze_trace` | Посчитать метрики по trace |
| `review_calibr` | Показать calibr-карточки на ревью |

## Как просить LINZA в чате

Если путь к файлу неизвестен, попросите LINZA найти материалы по теме. Обычно за этим стоит `search`, а точный файл потом открывается через `read_file`.

Если нужно понять состояние всей папки, попросите проверить папку и показать карту. Это соответствует `agent_workspace(action="doctor")` и `agent_workspace(action="map")`.

Если агент предлагает изменить сайдкар или компактный YAML, сначала попросите показать карточки ревью и предварительный просмотр. Внутри это `review_next`, затем `apply_review_items` с `dry_run=true`. Реальная запись требует точных ID и явного `dry_run=false`.

Если нужно передать контекст в новую сессию, попросите собрать пакет контекста. Он сохраняется в `.linza/context-packs`.

## Дополнительный режим

Для разработки и аудита можно открыть полный список инструментов:

```powershell
$env:LINZA_TOOL_SURFACE="advanced"
```

В этом режиме появляются низкоуровневые операции: `index_file`, `write_file`, `patch_properties`, профили поиска, tag-аудит, отчеты, `build_review_apply_queue`, `approve_review_queue_items`, `show_flow`, `create_context_pack` и диагностические команды.

`write_file` в этом режиме работает только с Markdown и требует явного `allow_overwrite=true` для замены существующего файла. Обычный маршрут LINZA строится вокруг карточек ревью и сайдкар-записей.
